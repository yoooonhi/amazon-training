# 第5节 · 9810通关通道

## 一、什么业务适合9810

9810适用于以下真实业务链路：

> 境内企业把货物通过跨境物流发往境外仓库 → 货物入海外仓 → 后续通过跨境电商平台实现交易 → 从海外仓交付境外买家

Amazon FBA通常符合这一业务形态，但企业必须能够提供真实的店铺、Shipment、海外仓入库和后续销售证据。

以下情形不要机械套用9810：

- 货物已经直接销售给境外企业并直发客户
- 没有真实海外仓或平台销售链路
- 物流商只提供普通0110报关
- 使用其他企业抬头“买单出口”

## 二、取消的是备案，不是数据

现行规则已取消跨境电商出口海外仓企业的单独业务模式备案，但申报时仍需传输：

- 海外仓订仓单/订单电子数据
- 交易电子信息
- 物流电子信息
- 报关单或申报清单数据

跨境电商出口申报已不再要求传输收款单电子信息，但企业仍需为交易、物流和订仓数据的真实性负责。

## 三、筛选物流商和报关行

不要只问“能不能发Amazon”。把以下问题逐条发给对方：

1. 是否支持监管方式9810，而不是0110或其他代码？
2. 能否以深圳示例公司作为“境内发货人”？
3. 通过哪个单一窗口或跨境电商通关平台传输数据？
4. 谁负责传输交易、订仓和物流数据？
5. 是否生成本企业抬头的完整9810出口报关单？
6. 报关数据能否正常传送至税务系统？
7. 报关前是否提供预录入草单审核？
8. 出口后能否提供放行、离境和结关状态？
9. 商品HS编码和申报要素由谁确认？
10. 查验、改单、退关和退运分别如何收费？

如果对方只回答“包税双清、什么都不用管”，却不能回答监管方式、数据通道和报关单抬头，不应作为9810服务商。

## 四、建立电子代理报关委托

企业自己不是报关企业时，可以委托专业报关行：

1. 确认报关行全称、统一社会信用代码和海关编码
2. 登录国际贸易单一窗口相关委托模块
3. 发起或确认电子代理报关委托
4. 明确委托期限和业务范围
5. 保存电子委托关系和报关服务合同

电子委托只授权对方代办报关，不代表可以让对方擅自改变商品编码、价格或企业抬头。

## 五、“自己企业抬头”看哪个字段

报关单上重点看：

| 字段 | 要求 |
|---|---|
| 境内发货人 | 深圳示例公司的完整法定名称 |
| 统一社会信用代码 | 本企业代码 |
| 海关注册编码 | 本企业取得的海关编码 |
| 监管方式 | 9810 跨境电子商务出口海外仓 |
| 生产销售单位 | 按实际生产、采购和销售关系填写 |

“报关行名称出现在申报单位”并不等于用了报关行抬头；真正决定出口主体的是境内发货人等企业字段。

## 六、建立平台数据对应关系

至少能够形成：

```text
Amazon店铺
  └─ FBA Shipment ID
       ├─ 海外仓地址
       ├─ SKU / ASIN / FNSKU
       ├─ 订仓或入仓计划
       ├─ 国内装箱单
       ├─ 物流单号/提运单
       └─ 9810报关单
```

Shipment发生拆分、改仓、拒收或部分入库时，应保留前后版本，不能只保留最终截图。

## 七、服务合同至少写清楚

- 监管方式必须为9810
- 境内发货人为本企业
- 数据传输主体及责任
- 报关资料审核和改单机制
- 查验费用及货损责任
- 报关单、放行和结关资料交付
- 禁止未经授权变更抬头或买单出口
- 商业数据和账号信息保密

## 本节完成标准

- [ ] 已确认业务真实符合9810
- [ ] 服务商明确支持9810电子数据传输
- [ ] 已建立电子代理报关委托
- [ ] 合同明确使用本企业抬头
- [ ] 能在申报前拿到报关草单
- [ ] 能在出口后取得完整报关单和状态证明
- [ ] FBA Shipment与报关批次可以对应
